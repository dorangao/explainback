# ExplainBack local MVP implementation plan

**Goal:** Build and verify the bilingual explain → clarify → hint → transfer → compare loop locally.

**Architecture:** Dependency-free Node HTTP server, static browser workspace, server-only Meta adapter. Ephemeral sessions contain synthetic adult examples only. No database, accounts, uploads, deployment or remote repository changes.

**Visual thesis:** A quiet paper-like math notebook with dark ink, teal actions, and a generous graph plane.
**Content plan:** Working problem and explanation; targeted feedback; deterministic graph revealed after reflection; fresh transfer; before/after reasoning.
**Interaction thesis:** Stage changes reveal the next action, feedback enters with a short fade, controls have restrained hover/focus feedback; respect reduced motion.

## Constraints
- `.env.local` stays server-side and ignored; never print its values.
- Local IPv4 loopback only; explicit static-file allowlist; reject foreign origins and unexpected Host headers.
- Synthetic adult-user examples only. No student data or public access.
- Three checked misconception families: asymptote crossing, finite nonzero limits, and unequal end behavior.
- Model assessments are tentative. Ambiguity produces clarification; successful transfer is evidence for this problem, not lasting mastery.
- One request per turn; bounded inputs, sessions and attempts; no automatic paid retries.

## Review focus
- A vague learner statement must not be called wrong merely for language ambiguity.
- An upstream failure must preserve the learner's text and permit an explicit retry.
- Rapid or repeated submissions must not cause duplicate paid requests.
- A reset while a request is pending must not apply stale feedback.
- Graphs must use verified formulas and clearly label end behavior and crossings.

Execution is inline in the current session, as requested by the user. This folder has no Git repository; no commits are created.
